# OJ 3544: ระบบจัดการคลังสินค้า

---

## 1. โจทย์จริงจาก iJudge

บริษัทแห่งหนึ่งต้องการพัฒนาระบบประมวลผลคำสั่งคลังสินค้า โดยคำสั่งที่ถูกส่งเข้ามาจะต้องถูกนำไปเข้าคิวเพื่อประมวลผลตามลำดับก่อน-หลัง (First-In, First-Out) และจัดเก็บข้อมูลสต็อกสินค้าอย่างเป็นระเบียบรายละเอียดของระบบการรับคำสั่ง
รายละเอียดคำสั่งที่โปรแกรมต้องรองรับ
คำสั่งจะถูกป้อนเข้ามาทีละบรรทัด โดยมีรูปแบบดังนี้:

- ADD <ชื่อสินค้า> <จำนวน>
เพิ่มจำนวนสินค้าลงในคลัง (ถ้ายังไม่เคยมีสินค้านี้ ให้เพิ่มเป็นสินค้าชนิดใหม่)

- REMOVE <ชื่อสินค้า> <จำนวน>
ลดจำนวนสินค้าในคลัง
หากสินค้ามีพอ ให้ลดจำนวนตามปกติ (ไม่ต้องแสดงผลอะไร)

  หากสินค้ามีไม่พอ (หรือยังไม่มีสินค้านี้ในระบบ) ให้ปรับจำนวนสินค้านั้นให้เหลือ 0 และแสดงข้อความ:
Not enough stock for <ชื่อสินค้า>

- CHECK
ตรวจสอบสินค้าที่มีจำนวนน้อยกว่า 5 ชิ้น
หากพบ ให้แสดงชื่อสินค้าเหล่านั้น บรรทัดละ 1 ชนิด (เรียงตามตัวอักษร A-Z)

  หากไม่มีสินค้าใดต่ำกว่า 5 ชิ้นเลย ให้แสดงข้อความ:
All stocks are sufficient

- REPORT
แสดงรายการสินค้าทั้งหมดที่มีอยู่ในคลัง เรียงตามชื่อสินค้า (จากมากไปน้อย) บรรทัดละ 1 ชนิด ในรูปแบบ:
<ชื่อสินค้า>: <จำนวน>


- END
สิ้นสุดการรับคำสั่ง และจบการทำงานของโปรแกรม

## 2. Input Specification

บรรทัดที่ 1 ถึง บรรทัดที่ N-1: สตริงคำสั่งการทำงานทีละคำสั่ง โดยแต่ละบรรทัดจะเป็นหนึ่งใน 4 รูปแบบต่อไปนี้ 
- ADD
- REMOVE
- CHECKREPORT
- REPORT

บรรทัดที่ N :
- END

## 3. Output Specification

บรรทัดที่ 1 ถึง บรรทัดที่ N: ข้อความผลลัพธ์จากการประมวลผลคำสั่งตามลำดับในคิว

## 4. ตัวอย่างจาก iJudge

### ตัวอย่างที่ 1
- **อินพุต**:
  ```text
  ADD Apple 10
  ADD Banana 5
  REMOVE Apple 3
  REPORT
  END
  ```
- **เอาต์พุต**:
  ```text
  Apple: 7
  Banana: 5
  ```

### ตัวอย่างที่ 2
- **อินพุต**:
  ```text
  ADD Milk 12
  ADD Bread 6
  CHECK
  REPORT
  END
  ```
- **เอาต์พุต**:
  ```text
  All stocks are sufficient
  Bread: 6
  Milk: 12
  ```
